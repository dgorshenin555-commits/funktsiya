# CHANGELOG — инкрементальные итерации дизайна «Функция»

> **Как это читать (инструкция для Claude Code / разработчика):**
> Этот файл — журнал правок дизайна, отправляемых пакетами. Каждая «Итерация» —
> это **дельта**: только то, что изменилось с прошлого раза.
>
> **Применяйте ТОЛЬКО итерации со статусом `НЕ ВНЕДРЕНО`.** Итерации со статусом
> `ВНЕДРЕНО` уже есть в кодовой базе — НЕ переделывайте их заново. После внедрения
> разработчик (или вы) меняет статус итерации на `ВНЕДРЕНО` и фиксирует дату.
>
> `README.md` — это полный базовый справочник по дизайну (токены, экраны, поведение).
> Он отражает **актуальное целевое состояние** и обновляется вместе с итерациями.
> При конфликте README и CHANGELOG — приоритет у README как у итогового состояния,
> а CHANGELOG объясняет, *что именно* поменялось в последней посылке.

## Итерация 3 — Полная унификация дизайн-системы (.fx) по всему приложению
**Дата:** 2026-06-17
**Статус:** ВНЕДРЕНО (2026-06-17)
**Область:** визуальный слой всех оставшихся экранов. Маршруты/логику/данные НЕ трогали.

> Не отдельная дизайн-посылка, а доведение всего приложения до единой дизайн-системы
> по запросу: «проверь все остальные страницы, чтобы они были изменены согласно нашим
> блокам». До этого на новый дизайн были переведены лишь orders/landing; остальные 11
> позиций оставались на легаси (`globals.css`/`.dsn-*`/`.order-card` + эмодзи). Перенос
> выполнен по эталонным референсам `screens_*.jsx` + `components.css`/`layouts.css`,
> весь новый CSS заскоуплен под `.fx` (для landing — `.tl`, для auth — `.authx` внутри `.fx`).

Что переведено на `.fx` (логика/маршруты/стор/обработчики сохранены дословно):
1. **Лендинг** (`app/page.tsx`): добавлено мега-меню «Главное меню» (`SECTIONS`, `tl-mega*`),
   GridPattern/GridCard, мобильные группы. Hero/auth-ветка/PromptBox сохранены.
2. **Очередь 1:** `settings` (settings-wrap/rolecard/field), `chat` (convitem/bubble/compose),
   `dashboard` (page-head/grid-3/stat/empty).
3. **Очередь 2:** `expertise` (биржа: pill-tabs/exch-grid/viewtoggle) + новый `expertise/detail`;
   `designers/[id]` (profile-hero/tabs/badge).
4. **Очередь 3:** каталоги `designers` и `experts` (cat-head/PromptSearch/RateScale/PersonCard/spotlight).
5. **Очередь 4.1:** `auth` → сплит-экран `.authx` (анимированные персонажи, show/hide пароля).
   Карточки ролей — SVG-иконки `_orders` вместо эмодзи (building/pen/shield/factory).
6. **Очередь 4.2 (ИИ-хабы):**
   - `standards` (Нормативы): `nb-hero`+ИИ-поиск, ИИ-разбор задачи, подсветка совпадений,
     библиотека-сетка, выезжающая панель документа (Drawer) с копированием кода.
   - `manufacturers` (Производители): 3 вкладки (ИИ-подбор/Производители/BIM), `ai-hero`,
     SolChart (mcard/mrow), карточки решений + slide-over с кольцом совпадения, BIM-библиотека.
   - CSS-фундамент: namespace `nb-*`/`ai-*`/`mcard`/`solm`/`secgrid` перенесён из эталона.
7. **Финальный аудит:** `analytics` (единственная страница на легаси) → `.fx`
   (page-head/stat/delta/.an-*). Эмодзи вычищены по всему приложению (кроме типографских ★
   в рейтингах и легаси-экрана orders/detail not-found — преекзистинг).

> **Терминология (важно):** остатки «Экспертиза»/«Эксперты» в телах каталогов
> (`experts`/`expertise`), `cz-tabs` превью лендинга, ролях авторизации и названиях
> компаний — оставлены **намеренно**, как зафиксировано в Итерации 1 (раздел «намеренно
> НЕ трогали»). Это соответствие эталону, а не недоработка.

> **NB:** Незакоммиченные файлы `app/_orders/shared.tsx`, `orders/detail`, `orders/new`,
> `lib/mock-data.ts` на старте сессии содержали правки не моего авторства — опубликованы
