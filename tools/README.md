# Перенос варианта Б из Cloud Design

Вариант Б (`app/v2/`) не пишется руками — он генерируется из выгрузки
Cloud Design, которая лежит в `design-handoff-v2/`. Правки вносятся
в исходники, а не в сгенерированные файлы: иначе они пропадут при
следующей пересборке.

## Как обновить после новой выгрузки

1. Положить свежие файлы в `design-handoff-v2/`
2. Прогнать оба скрипта:

```bash
python3 tools/scope_css.py      # new_design.css  -> app/v2/v2.css
python3 tools/transform_jsx.py  # new_design*.jsx -> app/v2/_screens/
npm run build                   # проверить, что собирается
```

## Что делают скрипты

**`scope_css.py`** загоняет все селекторы под класс `.nd`. Это нужно,
потому что вариант А держит стили в `app/globals.css` без всякого скоупа —
там глобальные `.btn`, `.card`, `:root` с токенами. Без скоупа два дизайна
дерутся за одни и те же имена. Внутри `@keyframes` селекторы не трогаются,
внутри `@media` — префиксуются.

**`transform_jsx.py`** переводит браузерные модули в модули Next.js:

- снимает обёртку `(function () { ... })()`
- добавляет `"use client"` и импорт React
- заменяет регистрацию в `window` на реестр `SCREENS` (см.
  `app/v2/_screens/registry.js`) — так сохраняется исходная схема
  «модули видят друг друга» без циклических импортов
- переводит строковые пути картинок на статические импорты через
  `app/v2/_assets.js`, иначе на GitHub Pages они ломаются о `basePath`

## Подводные камни

- `request_form.jsx` должен импортироваться **первым**: мастер заявки
  и каталоги читают из него данные в момент импорта, а не при рендере
- `OrderNew` объявлен дважды; рабочая версия — в `new_design_wizard.jsx`,
  в `new_design_flow.jsx` лежит облегчённая под именем `OrderNewLite`
- четыре картинки (`hero-*-2.png`, `tehnosfera-logo.jpg`) пока подменены
  аналогами варианта А — оригиналы не выгружаются через API, он режет
  файлы на 256 КБ. Заменить в `app/v2/_assets.js`, когда появятся

Подробности схемы — в `docs/superpowers/specs/2026-08-14-variant-b-parallel-design.md`.
