# Скрипты переноса варианта Б из Cloud Design

## Коротко: эти скрипты уже отработали, повторно их не запускают

Вариант Б (`app/v2/`) один раз импортировали из выгрузки Cloud Design,
которая лежит в `design-handoff-v2/`. С тех пор экраны развиваются
вручную — подключены к общему хранилищу `lib/`, работают с реальными
заявками, знают модель исполнителя. Генератор ничего этого не умеет,
поэтому повторный прогон просто откатит файлы к состоянию выгрузки
и сотрёт всю доработку.

Оба скрипта это знают и по умолчанию **откажутся работать**, если целевые
файлы уже на месте. Обойти отказ можно флагом `--overwrite`, но делать
это стоит только осознанно и с чистым рабочим деревом.

**`app/v2/_screens/*.jsx` — обычный код. Правьте его напрямую.**

## Что делать, когда придёт новая выгрузка из Cloud Design

Не перегенерировать, а переносить точечно:

1. Положить свежие файлы в отдельную папку, например `design-handoff-v3/`
2. Сравнить с тем, что уже есть: `diff -u design-handoff-v2/new_design.jsx design-handoff-v3/new_design.jsx`
3. Перенести в `app/v2/_screens/` только те куски, которые действительно
   нужны, руками — сохраняя доработки, которых в выгрузке нет
4. `npm run build` и глазами проверить `/v2`

Со стилями так же: `app/v2/v2.css` — сгенерированный файл, но правится
на месте. Если из Cloud Design приехал новый CSS, сравнивайте
и переносите нужное, а не заменяйте файл целиком.

## Что скрипты делали при первичном импорте

Пригодится, если однажды придётся переносить с нуля ещё один вариант.

**`scope_css.py`** загонял все селекторы под класс `.nd`. Это нужно,
потому что вариант А держит стили в `app/globals.css` без всякого скоупа —
там глобальные `.btn`, `.card`, `:root` с токенами. Без скоупа два дизайна
дерутся за одни и те же имена. Внутри `@keyframes` селекторы не трогаются,
внутри `@media` — префиксуются.

**`transform_jsx.py`** переводил браузерные модули в модули Next.js:

- снимал обёртку `(function () { ... })()`
- добавлял `"use client"` и импорт React
- заменял регистрацию в `window` на реестр `SCREENS`
  (см. `app/v2/_screens/registry.js`) — так сохраняется исходная схема
  «модули видят друг друга» без циклических импортов
- переводил строковые пути картинок на статические импорты через
  `app/v2/_assets.js`, иначе на GitHub Pages они ломаются о `basePath`

## Что полезно знать про вариант Б

- `request_form.jsx` импортируется **первым**: мастер заявки и каталоги
  читают из него данные в момент импорта, а не при рендере. Порядок
  импортов задан в `app/v2/page.jsx` — не переставляйте его бездумно
- `OrderNew` объявлен дважды: рабочая версия в `new_design_wizard.jsx`,
  в `new_design_flow.jsx` лежит облегчённая под именем `OrderNewLite`
- стили Б заскоуплены под `.nd`, поэтому переход между вариантами А и Б
  делается обычным `<a href>`, а не `<Link>` — иначе клиентская навигация
  затащит CSS обоих вариантов в один документ
- четыре картинки (`hero-*-2.png`, `tehnosfera-logo.jpg`) подменены
  аналогами варианта А: оригиналы не выгружаются через API Cloud Design,
  он режет файлы на 256 КБ. Заменить в `app/v2/_assets.js`, когда появятся
